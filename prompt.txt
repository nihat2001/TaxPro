## 0. Rol və Məqsəd

Sən **Senior Python & LangGraph Engineer**-sən. Tapşırığın: **TaxPro** — Azərbaycan dövlət vergi/bank portalları üçün Chrome Extension-la işləyən, **async, modulyar, istehsalata-hazır (production-ready)** Python backend qurmaqdır.

Backend-in əsas vəzifəsi: istifadəçinin əvvəlcədən saxladığı profil məlumatlarını (VÖEN, Asan ID, PIN/PUK və s.) Chrome Extension vasitəsilə rəsmi bank/vergi saytlarının giriş formalarına **avtomatik doldurmaq (auto-fill)** üçün təmiz JSON API təqdim etməkdir. Bundan əlavə, Excel idxalı və bank çıxarışı təhlili üçün AI agent qatı var.

## 3. İkiqat İcra Rejimi

### 3.1 Deterministik Rejim (AI çağırılmır ❌)
- Profil yaratmaq / redaktə etmək / silmək / siyahılamaq (CRUD).
- Portallar siyahısını vermək və auto-fill payload-u hazırlamaq.
- **Standart şablona uyğun** Excel/CSV oxumaq və birbaşa DB-yə yazmaq (Pandas/OpenPyXL).

### 3.2 AI / Agent Rejimi (yalnız lazım olduqda 🤖)
- Sütunları/forması **pozulmuş** Excel faylı → `unstructured_parser_agent`.
- Bank çıxarışı (PDF/Excel) → `bank_vat_agent`.
- Çat pəncərəsində sual → `profile_data_retriever_agent`.

Router qaydası: gələn sorğu əvvəlcə "bu standart əməliyyatdırmı?" testindən keçir → əgər bəli, AI **heç çağırılmır**; əgər xeyr, `supervisor_agent` işə düşür.

## 4. LangGraph Supervisor Arxitekturası — Texniki Tələblər

1. **Supervisor pattern**: `supervisor_agent` gələn sorğunu analiz edir və `Command(goto=...)` ilə müvafiq worker agent-ə yönləndirir (handoff, tool-call formatında).
2. Hər worker agent işini bitirdikdə **yenidən `goto="supervisor"`** ilə nəzarəti qaytarır (round-trip pattern).
3. **State**: Nested `TypedDict` strukturu istifadə et (məs. `AgentState(TypedDict)` içində `messages`, `current_agent`, `attempt_count: dict[str, int]`, `task_result` sahələri).
4. **Recursion limit**: Graph invoke zamanı `recursion_limit` konfiqurasiya edilməli (məs. 25) — sonsuz dövrənin qarşısını almaq üçün.
5. **Max cəhd sayğacı**: Hər agent üçün `TypedDict` daxilində cəhd sayğacı saxla; müəyyən agent N dəfədən çox uğursuz olarsa, graph avtomatik `error_handler` node-una yönləndirilməlidir.
6. **Human-in-the-loop (HITL)**: Həssas əməliyyatlar üçün (məs. bank çıxarışı əsasında profil məlumatlarının avtomatik dəyişdirilməsi) `interrupt_before=["sensitive_write_node"]` konfiqurasiyası tətbiq et ki, istifadəçi təsdiqi olmadan yazma baş verməsin.
7. Bütün agent icrası **asinxron** (`async def`) olmalıdır.

## 5. Agentlərin Vəzifə Bölgüsü

| Agent | Vəzifə |
|---|---|
| `supervisor_agent` | Sorğunu analiz edir, `goto` ilə uyğun worker-ə yönləndirir |
| `unstructured_parser_agent` | Sütun adları qarışıq Excel/CSV-ni semantik anlayır (məs. "Vergi Nömrəsi" / "VÖEN kodu" → `voen`), Pydantic modelinə map edir, DB-yə yazır |
| `bank_vat_agent` | Bank çıxarışını (PDF/Excel) analiz edir, ƏDV-yə cəlb olunan və xərcə silinən məbləğləri kateqoriyalaşdırır |
| `profile_data_retriever_agent` | Çatdakı sualları (məs. "Əhmədin Asan ID-si nədir?") pgvector/SQL sorğusu ilə tapıb dəqiq cavablandırır |

## 6. Verilənlər Bazası Modelləri

### `Profile` (Asan İmza Pro ekran görüntüsündəki sahələrə uyğun)
```
id: UUID (PK)
ad_soyad: str
voen: str
nomre: str            # telefon nömrəsi
asan_id: str
bitme_tarixi: date | None
qeyd: str | None       # "yenilənib / gözləyir"
pin1: str (encrypted)
pin2: str (encrypted)
puk: str (encrypted)
rəng: str              # profil rəngi (UI üçün)
ikon: str              # profil ikonu (UI üçün)
created_at, updated_at: datetime
```
⚠️ **Təhlükəsizlik tələbi**: `pin1`, `pin2`, `puk` sahələri DB-də **şifrələnmiş** (məs. Fernet/AES) saxlanmalı, API cavabında maskalanmalıdır (`****`), yalnız auto-fill sorğusunda extension-a açıq göndərilməlidir (HTTPS üzərindən).

### `Portal`
```
id, name, url, category (dövlət/bank), logo_url, selector_mapping (JSON)
```

### `VectorDocument` (pgvector)
```
id, profile_id (FK, nullable), content, embedding (vector), source_type (note/excel/bank_statement)
```

## 7. API Endpoint-lər (Nümunə Kontrakt)

```
POST   /api/v1/profiles                → Yeni profil yarat (deterministik)
GET    /api/v1/profiles                → Profil siyahısı
PUT    /api/v1/profiles/{id}           → Redaktə et
DELETE /api/v1/profiles/{id}           → Sil

GET    /api/v1/portals                 → Bütün portal/bank siyahısı (Extension üçün)
GET    /api/v1/autofill/{profile_id}/{portal_id}  → Auto-fill payload (JSON, field→value)

POST   /api/v1/import/excel            → Excel yüklə (avtomatik deterministik/AI seçimi backend-də edilir)
POST   /api/v1/bank-statements/analyze → Bank çıxarışı təhlili (AI)

POST   /api/v1/chat                    → RAG çat sorğusu (profile_data_retriever_agent)
```

Bütün cavablar **təmiz JSON**, bütün endpoint-lərdə **CORS aktiv** (Chrome Extension origin-ləri üçün).

---

## 8. Chrome Extension İnteqrasiya Qaydası

1. Extension `GET /api/v1/portals` ilə saytlar siyahısını çəkir, "Saytlar" bölməsində göstərir.
2. İstifadəçi saytın üstünə kliklədikdə rəsmi portal **yeni tabda** açılır (bu, backend-də deyil, extension-da həyata keçirilir — backend yalnız `url` verir).
3. İstifadəçi "Doldur" düyməsinə basdıqda extension `GET /api/v1/autofill/{profile_id}/{portal_id}` çağırır, qaytarılan `field → value` map-ini portal `selector_mapping`-i ilə uzlaşdırıb aktiv tab-dakı input-lara yazır (`content script`).
4. Profil yaratma/redaktə formaları birbaşa `POST/PUT /api/v1/profiles` çağırır.
